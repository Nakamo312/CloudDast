# QDL Security Algebra

Canonical specification of the closed basis, the algebra over it, and the
derivations of STRIDE / OWASP classes.  This document is the source of truth
for the formal layer; the Clingo rules in
`cloud_dast/qdl/engine.py` implements it and
`tests/application/verification/formal/test_qdl_algebra.py` checks corpus
derivability and closure properties on finite fixtures. These checks do not
prove completeness for arbitrary security norms.

## 1. Design discipline

The basis never grows to describe a vulnerability class.  Classes are
*formulas* over the basis.  New names (`leak`, `spoof`, `ssrf`, ...) are only
allowed as **definitional extensions** — conservative abbreviations that
eliminate back into the basis.  A primitive is added only when a class is
proven inexpressible, and that is an event, not a routine.

## 2. Basis Σ

### 2.1 Sorts

| Sort | Meaning |
|---|---|
| `Sub` | subjects: users, service accounts, roles, attacker, auditor |
| `Act` | actions: API calls, operations, transitions |
| `Eff` | effects: deltas of world state |
| `Wit` | witnesses: everything a subject can measure |

Objects and fields are embedded in structured terms of actions and effects;
they are not a standalone sort in this conceptual table. `Res` and `Node`
in the signatures below denote resource and graph-node positions.

These are semantic roles, not a proved runtime sort system. The existing
`qdl/graph.py` registries validate predicate/constructor arity, literal
kinds, permitted constructor names and declared references; `QdlGraph` also
checks grounding, duplicate statements and rule safety. Variables are checked
for binding, not inferred semantic sorts. Declarations are collected across
the graph, not required in each reference's context. In particular,
`is(r, Resource), is(p, Permission), executes(r, p)` passes validation despite
violating the intended `Sub × Act` signature. A declaration proves reference
closure, not membership in an enforced semantic sort. No full semantic sort
soundness result is currently established.

### 2.2 Effect constructors (closed)

State of a distributed system decomposes into five components, therefore
effects decompose the same way:

| Constructor | State component |
|---|---|
| `write(o, f, v)` / `changed(o, f)` | stores: field values |
| `grant(s, p)` / `has(s, v)` | policy: granted rights |
| `transition(q, q')` | control state of the state machine |
| `create(o)` / `remove(o)` | object registry |
| `call(x)` / `external_call(a, m)` | environment: outbound calls |

### 2.3 Witness constructors (closed) — channel lemma

Everything an attacker can measure about an API interaction is generated by
six witness constructors:

| Constructor | Measurable | Primitive oracle |
|---|---|---|
| `field(r, f)` | response field value | П2 |
| `status(a)` | outcome code | П1 |
| `error(a)` | diagnostic message | П5 |
| `latency(a)` | response time | П4 |
| `callback(a, m)` | outbound side effect | П3 |
| `trace(a)` | cross-request observability | П6 |

*Proof sketch.* An interaction is request → system → response + side effects.
The measurable surface is: the response document (fields, statuses,
diagnostics), response metadata (timing), external effects (callbacks), and
state effects observable through later requests (traces).  Any measurement is
a function of these, hence the constructors generate all witnesses.  Physical
channels (power, EM, acoustics) are outside the API interaction model. ∎

### 2.4 Primitive predicates (six)

| Predicate | Signature | Substrate |
|---|---|---|
| `executes` | `Sub × Act` | who really initiated the action |
| `binds` | `Wit × Sub` | which evidence truly binds a subject |
| `may` | `Sub × Act × Res` | what policy permits (permits) |
| `causes` | `Act × Eff` | what an action causes |
| `observes` | `Sub × Wit` | who can witness what (confidentiality) |
| `reaches` | `Node × Node` | direct reachability: dataflow, network, dependency |

`reaches_plus` is the transitive closure of `reaches` (Section 6).

### 2.5 Grounded model predicates (not part of Σ)

The language is closed; the model is semantically open.  These predicates are
grounded by the LLM semantic compiler into the model `M` and never extend Σ:

| Predicate | Signature | Meaning |
|---|---|---|
| `exposes` | `Act × Wit` | action exposes a witness channel |
| `accepts` | `Act × Wit × Sub` | system accepts witness as credential of subject |
| `required` | `Sub × Res` | availability norm: user requires resource |
| `targets` | `Act × Res` | action targets resource |
| `owner` | `Res × Sub` | resource owner |
| `has` | `Term × Role` | structural role of a term |
| `is` | `Term × Kind` | typing / declaration |

## 3. The six letters — definitions

```
S(a,w,s) := accepts(a,w,s) ∧ ¬bound(w,s)
T(a,s)   := executes(s,a) ∧ targets(a,r) ∧ current_effect(a,e)
            ∧ ¬permitted(s,a,r)
R(a,s)   := executes(s,a) ∧ ¬audited(a)
I(s,a,w) := exposes(a,w) ∧ observes(s,w) ∧ targets(a,r)
            ∧ ¬permitted(s,a,r)
D(u,r)   := required(u,r) ∧ ¬reachable(u,r)
E(s,a)   := executes(s,a) ∧ targets(a,r) ∧ ¬permitted(s,a,r)
```

Here resource/effect variables in a rule body are existential witnesses for
its head. These are the complete bodies of the current Clingo definitions,
not a mapping from a single primitive atom to a letter. `bound`, `permitted`,
`audited` and `reachable` denote the existing `_algebra_*` projections:
`binds`, exact `may(s,a,r)`, `observes(auditor,trace(a))` with
`is(auditor,"auditor")`, and `reaches_plus`, respectively. They erase context
only after `_algebra_view` restricts inputs to `contract` and `accepted`.
`current_effect` excludes superseded effects. Generic QDL rules keep their
literal's concrete `Context`; the library closure rules explicitly bind `C`.
`find_path(context=c)` joins every edge premise on that same `c`.

### Correspondence primitive ↔ letter

```
binds                        → S
causes × may                 → T
executes × observes(auditor) → R
observes × may               → I
reaches                      → D
executes × may               → E
```

Near-bijection.  `executes` is shared by S (attribution gap) and E
(authority gap) — this formalizes the canonical "steal credential → use it"
chain as an S→E sequence.

## 4. Algebra

### 4.1 Class algebra — Boolean ring (group structure)

`Def(Σ)` — all Σ-definable subsets of the violation universe `V`.
With symmetric difference `Δ`, intersection `∩`, `∅`, `V`:

- `(Def(Σ), Δ)` is an abelian group, every element self-inverse (`A Δ A = ∅`)
  — a vector space over GF(2);
- `∩` distributes over `Δ`, is idempotent, `V` is the identity;
- therefore `Def(Σ)` is a **Boolean ring** ⟺ Boolean algebra.

For a fixed grounded model and common universe, any finite family of
classification formulas generates a Boolean subalgebra under these
operations. This does not establish inclusion between taxonomy-generated
subalgebras. Six letter predicates yield at most 64 membership patterns;
63 have a nonempty letter set. The all-false pattern is possible even for a
norm violation (T2), and multiple letters can hold together.

### 4.2 Path algebra — monoid, not a group

Sequencing of actions composes: `v₂ ∘ v₁`.  Objects are states, morphisms
are action sequences: associative, identity (empty path), **no inverses** —
observation cannot be un-observed, grants and deletions are not universally
reversible.  Attack paths form the free category (monoid) over the state
graph.  This asymmetry is the mathematical form of the attacker/defender
asymmetry: the attacker needs one forward path; the defender would need all
inverse paths to exist, and they do not.

The reward machine is an automaton evaluating traces (morphisms); the bandit
and the LLM are navigation policies on this category.

### 4.3 Witness verdict semantics — strong Kleene three-valued logic

Primitive oracles do not decide arbitrary temporal properties from finite
traces.  Each observation supplies a partial valuation:

```text
val_o  : W ⇀ {0, 1, ⊥}
complete_o : C → {0, 1}
```

For an effect `e`, let `P(e)` be its positive witnesses and `N(e)` its
negative witnesses:

```text
T(e,o) ⇔ ∃w ∈ P(e): val_o(w) = 1

F(e,o) ⇔ N(e) ≠ ∅
         ∧ ∀w ∈ N(e):
              complete_o(channel(w)) = 1
              ∧ val_o(w) = 0

U(e,o) ⇔ ¬T(e,o) ∧ ¬F(e,o)
```

The deterministic verdict contract is therefore:

```text
FAIL        ⇔ T(e,o)
PASS        ⇔ F(e,o)
UNSCOREABLE ⇔ U(e,o)
```

Positive evidence is existential; negative evidence is universal and requires
a **local closed world** over explicitly complete channels.  Composition is
strong Kleene logic (`U ∧ U = U`, `F ∧ U = F`, `T ∨ U = T`), so `⊥` can never
collapse into truth.  In implementation terms, `PolicyVerdict.negative_scope`
names the complete channels behind every `PASS`; marker absence, an echo-only
marker, an unresolved principal scope, an unfinished sequence, or an ungrounded
expectation remains `UNSCOREABLE` and carries a typed oracle deficit.

Sink interpretation is not a verdict-layer vocabulary.  QDL `is(term, kind)`
facts bind a probe field to its sink kind; the declarative witness-role policy
then states whether that kind is a deterministic witness, a candidate that
needs another primitive, or merely unclassified for special marker handling.
Production vulnerability names and benchmark field names never participate in
this decision.

## 5. Theorems

### T1 — Closure

(a) `Def(Σ)` is closed under `∪, ∩, ¬` (closure of formulas under
connectives).

(b) Definitional extensions are conservative: a definition such as
`leak(s,w) :≡ observes(s,w) ∧ ¬permits_read(s,w)` eliminates into the basis;
`Def(Σ ∪ {leak}) = Def(Σ)`.

(c) Composed witnesses remain witnesses in the path monoid: violated
temporal formulas evaluate over concatenated traces.

### T2 — Cover for an explicitly restricted norm fragment

Fix a grounded model, the trusted context view, and the current letter
formulas `L₁,…,L₆` from Section 3, including **all** their premises. Consider
only norms of the form:

```
φ = ∧ⱼ ∀x (Gⱼ(x) → ¬Lᵢⱼ(πⱼ(x)))
```

Here `Gⱼ` is an explicitly specified guard and `πⱼ` selects the arguments
of one letter. For this fragment a falsifying assignment satisfies
`Gⱼ(x) ∧ Lᵢⱼ(πⱼ(x))` for some j, hence its projected tuple belongs to at
least one letter relation. This follows directly by negating the displayed
formula. Arbitrary Boolean combinations or arbitrary Σ-definable norms are
not in this fragment. The claim does not infer missing permission, target,
audit or witness premises from the occurrence of a primitive atom.

Countermodel to universal cover (checked with the existing Clingo algebra):

```
executes(s,a), targets(a,r), may(s,a,r), causes(a,create(r)),
observes(auditor,trace(a)), is(auditor,"auditor"), prevents(n,create(r))
```

With the required declarations, no other facts and no supersession, the norm
`¬causes(a,create(r))` is violated, but all six letter relations are empty.
Permission blocks T/E, the audit blocks R, and S/I/D lack their positive
premises. Removing `may(s,a,r)` derives T/E, a positive control. CNF
normalization cannot supply these missing premises. `prevents` norms can
therefore express violations outside this letter-cover fragment without
extending Σ or forcing a letter classification.

### T3 — Definability of implemented taxonomy formulas

Sections 7–8 define the implemented OWASP labels from letters plus grounded
structural predicates and current projections. Each such label can be
expanded into those defining formulas for a fixed model. This establishes
computable classification by the listed rules, not a refinement chain
`CWE ≼ OWASP ≼ STRIDE`, nor inclusion of their generated Boolean algebras.
No general CWE hierarchy is proved here.

For example, two models with the same unauthorized, audited action and
`create(r)` effect both have exactly T/E. Adding
`has(input_field(a,f),"privileged")` to only one model derives API3 only
there. Thus the six letter truth values alone do not determine the OWASP
labels. Even their combination with arbitrary structural facts establishes
only the forward definitions, not an invertible taxonomy projection.
`tests/test_review_F1.py` checks this countermodel and T2's permitted-create
countermodel with their positive controls.

## 6. Transitive closure

`reaches_plus` is the (non-reflexive) transitive closure of `reaches`:

```
reaches_plus(C, X, Y) :- reaches(C, X, Y).
reaches_plus(C, X, Z) :- reaches(C, X, Y), reaches_plus(C, Y, Z).
```

Properties (verified by tests):

1. **Termination**: positive recursion over a finite graph — Clingo computes
   the least fixpoint; cyclic graphs terminate.
2. **Transitivity**: `reaches_plus(X,Y) ∧ reaches_plus(Y,Z) → reaches_plus(X,Z)`.
3. **Idempotence**: `(reaches⁺)⁺ = reaches⁺` — closing the closure changes
   nothing.
4. **Stratification**: `reaches_plus` is positive-recursive; letters negate
   only lower strata (`binds`, `may`, `observes`, `reaches_plus`); corpus
   rules are positive over letters.  No cycle through negation — the program
   is stratified and grounds successfully.

## 7. Corpus derivations

### OWASP API Top 10

```
API1  BOLA                := E ∧ input_field(a, f) has object_ref
                               ∧ targets(a, o) ∧ owner(o) ≠ s
API2  BrokenAuth          := S ∨ (I ∧ witness has credential)
API3  MassAssignment      := T ∧ input_field(a, f) has privileged
API4  ResourceConsumption := D ∧ resource has unbounded
API5  FunctionAuthz       := E ∧ is(a, function)
API6  BusinessFlows       := T ∧ action has flow_step
API7  SSRF                := E ∧ causes(a, external_call(a, m)) ∧ is(m, external_net)
API8  Misconfig           := I ∧ witness has verbose
API9  Inventory           := E ∧ is(a, deprecated)
API10 UnsafeConsumption   := T ∧ action has downstream_trust
```

### OWASP Web Top 10

```
A01 BrokenAccessControl := E
A02 CryptoFailures      := (I ∧ witness has sensitive) ∨ (S ∧ witness has weak_binding)
A03 Injection           := T ∧ input_field(a, f) has attacker_controlled
                               ∧ reaches_plus(input_field(a, f), sink)
                               ∧ is(sink, interpreter)
A04 InsecureDesign      := defect of the norm φ itself — not a runtime witness class
A05 Misconfig           := cross-cutting manifestation (alias of API8 patterns)
A06 VulnComponents      := T ∧ action has component
A07 AuthFailures        := S
A08 IntegrityFailures   := T ∧ action has unverified_source
A09 LoggingFailures     := R
A10 SSRF                := API7
```

Injection is one formula with different sink kinds: `sql_engine`,
`browser_dom`, `template_engine`, `xml_parser`.  CWE numbers are report
labels on formulas, never generation inputs.

## 8. Transition STRIDE → OWASP

Both maps are Σ-definable and factor through the identity on `V`:

```
σ : V → 2^{S,T,R,I,D,E}       (STRIDE coordinates)
ω : V → 2^{OWASP classes}     (OWASP coordinates)
ω(v) = Φ(σ(v), struct(v))
```

| σ(v) | × struct(v) | → ω(v) |
|---|---|---|
| E | object_ref input, foreign owner | API1 BOLA |
| E | function | API5 |
| E | external_net reach | API7 / A10 SSRF |
| E | deprecated version | API9 |
| S | credential flow | API2 / A07 |
| T | privileged input | API3 |
| T | interpreter sink via dataflow | A03 Injection |
| T | downstream trust | API10 |
| D | unbounded cardinality/latency | API4 |
| R | audit | A09 |
| I | sensitive witness | A02 |
| I | verbose error | API8 |

The displayed rules compute OWASP labels from letters together with the
required grounded structural facts. They do not establish a reverse map
recovering all STRIDE coordinates from OWASP labels, or an inclusion between
the generated algebras. The computation is deterministic for a fixed model;
its classification remains a hypothesis rather than runtime proof.

## 9. Implementation mapping

| Algebra | QDL |
|---|---|
| `permits(s, a)` | `may(s, a, r)` (resource-scoped; `targets` links action → resource) |
| `executes`, `binds`, `observes(s, w)`, `reaches` | same-named predicates |
| evidence record (runtime) | `evidence(observation, effect)` |
| `reaches*` | closure `reaches_plus` |
| partial witness valuation | `PolicyVerdict.status` + `negative_scope` |
| sink role policy | QDL `is(term, kind)` facts + `witness_roles.yaml` |
| letters | derived atoms `spoofing/tampering/repudiation/disclosure/denial/elevation` |
| corpus | derived atoms `owasp_api1_bola` … `owasp_a10_ssrf` |

Runtime observation records were renamed `observes(observation, effect)` →
`evidence(observation, effect)` so that `observes` has exactly one meaning:
the confidentiality primitive `observes(subject, witness)`.

## 10. Threat modeling semantics

Threat modeling models *threats as hypotheses*, it does not assert
vulnerabilities.  Concretely:

- `executes(Attacker, Action)` is the **campaign hypothesis** — "the
  attacker attempts every action in scope" — added by the binder as a
  per-request fact, never claimed as truth about a person;
- `observes(Attacker, Witness)` is derived from `exposes` — "if the call
  returns, the attacker sees the witness";
- `may(Subject, Action, Resource)` is **derived from the IAM model**:
  `binding → grants → requires → targets`, refined by resource containment
  (`part_plus`);
- `owner(Resource, Subject)` is derived from resource-level bindings.

With these, the letters and corpus classes derive *statically* as the
threat model — the set of hypotheses to verify.  A runtime probe then
confirms or refutes each threat: DENIED means the gate holds (threat not
realized), OK means the threat is realized and becomes a finding.

## 11. Role of the LLM

The LLM never extends Σ.  It grounds the model `M` (roles, owners, sinks,
requirements) and navigates: given `M`, observation history, and coverage, it
proposes the next hypothesis as a formula over Σ.  The deterministic side
type-checks, compiles probes, executes fuzzing, and applies oracles.  The
bandit arbitrates between LLM-guided exploration and deterministic gap
enumeration.

## 12. Probe-carrier obligations

A marker or OOB norm requires an executable input carrier before active
probing. `probe_carrier(Action, Field)` is a derived query over existing QDL
facts, not a model-writable predicate. Its premises are a declared action,
a declared input field, and either a current trusted probe/OOB/privileged
role or `reaches_plus(input_field(Action, Field), Sink)` with a supported
source sink type. Only `contract` and `accepted` contribute these premises;
superseded roles do not contribute. The binder intersects this projection
with the executable method schema.

```text
needs_carrier(n) := oracle_primitive(n) ∈ {marker, oob_event}
ready(n, a, G)   := ∃ f ∈ inputs(a): probe_carrier(a, f, G)
deficit(n, a, G) := needs_carrier(n) ∧ ¬ready(n, a, G)
```

The missing query enters the existing deficit/work-item algebra. Its repair
route is `probe_carrier → reaches → dataflows`: a model proposes a flow from
a source-declared field to a source-typed sink, and deterministic promotion
checks those references. It cannot assert `probe_carrier` or engine roles.
Carrier selection authorizes a candidate input; it never establishes a
runtime sink witness or a verdict.

```text
deficit → bounded consultation → proposal → deterministic promotion
        → accepted graph → rebind → versioned path → runtime oracle
```

Pending logical paths remain visible. Preflight blocks a carrierless path
before its setup or active probes, without charging canonical execution
retries. A contract-only smoke path can still collect transport evidence
where no channel-ready path exists; it remains `UNSCOREABLE`. `changed`
uses the differential primitive and does not require a marker carrier.

Classification is a separate downstream obligation. A generic declaration
such as `is(Sink, Sink)` cannot satisfy a catalog's required security type:
closure must bind the type/role to the catalog's allowed-value alphabet.
Type lookup is a set-valued relation, so declaration order cannot affect
promotion or classification. Declaration closure is itself a promotion
boundary: accepting a semantic fact cannot copy a model-only input schema
or sink classification into `accepted` as a dependency. An invalid bundle
contributes neither orphan declarations nor promotion-budget usage.

For a method-scoped campaign, obligations range over the actions in its
selected paths, including predecessors, rather than the entire service.
This keeps the consultation budget aligned with the executable scope.
